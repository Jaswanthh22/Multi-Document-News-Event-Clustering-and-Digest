The 1-minute project explanation

“This project is a batch NLP pipeline for discovering real-world news events from multiple publishers. First, app.py reads RSS feeds, downloads the linked pages, extracts the main article text with Trafilatura, removes duplicate URLs, and saves valid records in articles.json. Second, cluster_headlines.py converts headlines into semantic sentence embeddings using all-MiniLM-L6-v2 and groups nearby embeddings with average-linkage agglomerative clustering using cosine distance. Singleton groups are removed and the remaining events are written to clustered_events.json. Third, summarize_events.py uses facebook/bart-large-cnn to summarize each article and then summarize the combined source summaries into one event digest, saved in news_digest.json. Finally, server.py exposes those artifacts through a small local API and the dependency-free frontend displays metrics, event cards, source perspectives, search, filters, and a live feed.”

Core idea: convert many noisy articles into a smaller set of semantic events, while preserving source-level evidence and original URLs.

Understand the why

Technical deep dive

Collection

Why RSS?

RSS gives a structured, lightweight list of recent stories and links. It is easier to automate than scraping a publisher homepage. The actual page is fetched afterward because RSS often contains only a title, link, and short metadata.

Extraction

Why Trafilatura?

News pages contain menus, ads, footers, and recommendation widgets. Trafilatura attempts to isolate the main article body, producing cleaner input for summarization than raw HTML.

Representation

What is a sentence embedding?

It is a dense numerical vector representing the meaning of text. Two headlines can be close even if they use different vocabulary, which is the key advantage over exact keyword matching.

Distance

What is cosine distance?

Cosine similarity compares the angle between vectors; cosine distance is commonly 1 − similarity. Smaller distance means more similar direction/meaning. The configured threshold is 0.38.

Clustering

Why agglomerative clustering?

It starts with each headline as its own group and progressively merges similar groups. Setting n_clusters=None with a distance threshold lets the data determine how many groups remain.

Linkage

Why average linkage?

When comparing two candidate clusters, average linkage uses the average pairwise distance between their members. It is a reasonable middle ground between single-linkage chaining and complete-linkage strictness.

Generation

What is BART doing?

BART is a sequence-to-sequence Transformer trained for denoising and fine-tuned here for news summarization. The encoder reads the input; the decoder generates a shorter output sequence.

Inference

Why two summarization passes?

The first pass keeps each publisher's perspective. The second pass combines those compact summaries into one event-level digest, while the original source summaries remain available for comparison.

Important parameter meanings

ParameterMeaningViva interpretation
normalize_embeddings=TrueScale embedding vectors to unit length.Makes dot-product geometry equivalent to cosine similarity and makes distances easier to compare.
DISTANCE_THRESHOLD = 0.38Maximum distance allowed for agglomerative merges.Lower = conservative clusters; higher = broader clusters. It is a manually selected hyperparameter.
max_length=1024Maximum input token length sent to BART.Long article input is truncated; information at the end may be lost.
num_beams=4Beam-search width during generation.Explores several candidate continuations and usually improves quality over greedy decoding.
do_sample=FalseDisable random sampling.Makes generation deterministic under the same model and runtime.
torch.no_grad()Disable gradient tracking.Appropriate for inference; reduces memory use because the model is not being trained.

Practice aloud

Likely viva questions and strong answers

Use the search box to find a topic. Open each question, answer in your own words first, then compare with the model answer.

1. What problem does this project solve?
Answer: It reduces information overload by grouping different articles that describe the same real-world event and producing a concise cross-source digest. The goal is event-level understanding, not just article-level search.
2. Explain the complete end-to-end flow.
Answer: RSS feeds provide recent links; app.py extracts article text into articles.json; cluster_headlines.py embeds and clusters headlines into clustered_events.json; summarize_events.py creates source summaries and a combined digest in news_digest.json; server.py merges these artifacts for the frontend dashboard.
3. Why did you use RSS feeds instead of scraping news homepages?
Answer: RSS is structured and already exposes recent story links and metadata. It is simpler and less brittle than scraping a changing homepage. I still fetch the linked page because RSS alone may not contain enough article text for summarization.
4. How is duplicate collection prevented?
Answer: Existing records are loaded first. Their URLs are placed in the seen set. Before fetching an RSS entry, the code checks whether entry.link is already in that set. A newly accepted URL is immediately added, so duplicates within the same run are also avoided.
5. Why skip extracted text with 300 characters or fewer?
Answer: Very short extraction often indicates an error page, paywall, empty body, or unusable fragment. The threshold is a simple quality filter. It improves downstream inputs, but it is heuristic and could wrongly exclude a genuinely short article.
6. Why use sentence embeddings instead of TF-IDF or keyword matching?
Answer: Keyword methods depend heavily on shared words. Sentence embeddings capture semantic meaning, so headlines such as “government approves emergency aid” and “officials authorize relief package” can be related even with different wording. TF-IDF would still be a useful baseline for comparison.
7. What is all-MiniLM-L6-v2?
Answer: It is a compact Sentence-Transformers model used to encode sentences into semantic vectors. It is a practical speed/quality choice for local headline clustering; it is not a classifier and it does not directly output event labels.
8. Explain the cosine-distance threshold of 0.38.
Answer: The clustering model can merge groups only when their distance is within the threshold. Because distance is lower for more similar vectors, lowering 0.38 creates smaller, stricter groups; increasing it creates larger, looser groups. The value is a manually chosen hyperparameter and should be validated on labeled examples.
9. How does agglomerative clustering work here?
Answer: It begins with one cluster per headline and repeatedly merges the closest clusters. With linkage="average", distance between clusters is based on average pairwise distance. n_clusters=None plus distance_threshold lets the algorithm stop merging based on the chosen distance rather than a preset number of clusters.
10. Why discard singleton clusters, and is the implementation truly multi-source?
Answer: A one-article group does not demonstrate corroboration or cross-article event detection, so the project removes it. However, the current code filters on article_count >= 2, not on distinct source count. Therefore, two articles from one publisher can remain. If multi-source is a hard requirement, the filter should be len(event["sources"]) >= 2.
11. Is the BART summary extractive or abstractive?
Answer: It is abstractive: the decoder generates new wording rather than selecting only existing sentences. That is why it can be concise and fluent, but also why factuality should be checked against the source articles.
12. Why summarize each article before combining them?
Answer: Combining full articles would make the input too long and could overwhelm the model. Per-article summaries compress each source first and preserve source attribution. The second pass then produces an event-level digest from that controlled-size comparison text.
13. What happens when an article is too long?
Answer: The code first caps raw text at 5,000 characters and then tokenizes with max_length=1024 and truncation=True. This avoids model input overflow, but it may remove important information near the end. A stronger system could use chunking and map-reduce summarization.
14. Why use four beams and disable sampling?
Answer: Four-beam search keeps several likely continuations and selects a high-scoring one. do_sample=False avoids random sampling, making results reproducible. This favors stable summaries over creative variation.
15. How does the code choose a compute device?
Answer: It uses PyTorch's mps device when Apple's GPU backend is available; otherwise it uses CPU. The model and tokenized tensors are moved to the same device. This is an inference optimization, not a change to the NLP algorithm.
16. Why have server.py if the data is already JSON?
Answer: Browsers are restricted when loading local files and the frontend needs one consistent payload. The server supplies static frontend files and exposes /api/data, which merges raw articles, clusters, summaries, metrics, and source counts. It keeps presentation logic separate from pipeline scripts.
17. What do the API endpoints do?
Answer: /api/data returns the merged dashboard payload with no-store caching. /api/health returns a small {"status":"ok"} response for a basic liveness check. Other GET paths serve files from frontend/.
18. Why does the frontend have escapeHTML?
Answer: Headlines, summaries, and URLs originate from fetched content. Before inserting them into template strings, special characters are escaped so data is treated as text rather than markup. This reduces the risk of HTML injection when rendering untrusted article content.
19. How would you evaluate the clustering quality?
Answer: Create a manually labeled set of related/unrelated headline pairs or event labels, then compare thresholds such as 0.30–0.45. Report pairwise precision, recall, and F1; for full clusters, use purity or adjusted Rand index. Also measure coverage: the fraction of collected articles assigned to retained events.
20. What are the main limitations?
Answer: The threshold is manually selected; clustering uses headlines only; a retained cluster need not contain distinct sources; long text is truncated; BART can hallucinate or merge conflicting reports; there is no labeled evaluation set, dependency lockfile, structured failure log, or factuality check. These are clear next steps rather than hidden assumptions.
21. What would you improve next?
Answer: First define the event contract and require two distinct sources if needed. Then add labeled threshold evaluation, pinned dependencies, retries/timeouts and structured run logs, explicit configuration, chunked summarization, body/entity signals for borderline clusters, conflict detection, and a one-command pipeline runner.
22. What ethical or practical concern exists for a news digest?
Answer: Source selection affects what the system can see, and a summary can omit context or amplify a model error. The dashboard should show publisher names and original links, preserve source summaries, and present the digest as an aid to reading rather than a replacement for source verification.

Answer with confidence

Limitations are not weaknesses if you can explain them

Threshold: 0.38 is a prototype setting. Say how you would tune it with labeled validation data.
Multi-source wording: The project says cross-source, but the current filter requires two articles, not two unique publishers.
Headline-only grouping: Short headlines can be ambiguous. Body text, named entities, dates, and locations could improve borderline cases.
Summarization risk: BART is generative. Preserve source summaries and original links, and add factuality/conflict review before production use.

Safe wording if the professor challenges the system

“This is an end-to-end working prototype, not a fully validated production news-monitoring system. I made the pipeline modular so each risk can be measured and improved independently: collection quality, clustering quality, summary quality, and presentation.”
